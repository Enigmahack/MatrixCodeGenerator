  1. Performance Bottlenecks

   * CPU Shadow Reveal Loop (Critical):
      In QuantizedShadow.updateShadowSim, the system iterates over the entire logic grid (~300k blocks) every frame to
  find revealed blocks, and then iterates over every revealed screen cell (~8.6k cells) to copy ~10 properties
  (character, color, alpha, glow, etc.) from the shadow grid to the main grid. This results in nearly 100,000 CPU
  writes every frame, which is a major bottleneck.
       * Optimization: Move shadow reveal blending to the GPU. The resolveShader already has access to shadow grid
         textures; it should calculate the reveal intensity (sFade) based on the block's birthFrame (passed via the
         logic grid texture) and the current animFrame.

   * Quadratic Operation Processing:
      In QuantizedBaseEffect._updateRenderGridLogic, the establishedMasks (used for connectivity and "smart" adds) are
  re-populated from Step 0 every time a new operation is added. As sequences grow (especially in the procedural
  engine), this becomes a quadratic performance hit.
       * Optimization: Update establishedMasks incrementally, just like the renderGrid and layerGrids.

   * Redundant Logic Grid Texture Updates:
      WebGLRenderer._renderQuantizedLineGfx re-builds and re-uploads the u_logicGrid texture every frame, even if no
  blocks were added or removed in the quantized logic.
       * Optimization: Use the existing fx._gridsDirty flag to skip these texture updates when the logic state is
         static.

   * Redundant Shadow Grid Buffering:
      WebGLRenderer performs a full screen-cell loop (~8.6k iterations) every frame to populate staging buffers for
  shadow grid uploads. This duplicates work already being done in other parts of the pipeline.

  2. Architectural Redundancies

   * Omni-class Bloat:
      QuantizedBaseEffect is mixed with the entire QuantizedProceduralEngine (~165KB of code) via a prototype mixin.
  This means simple effects like QuantizedPulse carry the overhead of massive growth algorithms, structural integrity
  checks, and "nudge" logic that they never use.
       * Refactoring: Separate the procedural engine into a decorator or only mix it into the specific
         QuantizedBlockGeneration subclass.

   * Canvas2D vs. GPU Overlap:
      The system maintains several shared canvases (gridCache, mask, lineMask) and calls _updateGridCache every frame,
  even though the comment in render() states that line rendering is now "GPU-only". While the shader uses the
  character index, the gridCacheCanvas itself appears to be a vestigial artifact from the legacy 2D pipeline.

  3. Alignment and Mapping

  The alignment logic in _computeCenteredOffset is now robust and correctly handles sub-pixel centering, but the
  redundant inclusion of offsets in both the logic grid mapping and the vertex shader occasionally causes "1-pixel
  line" artifacts at certain resolutions.

  Summary: The most impactful fix would be moving the Shadow Reveal logic entirely to the GPU, which would eliminate
  the majority of the per-frame CPU overhead in the quantized system.
